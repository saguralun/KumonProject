# KumonDB

ระบบจัดการนักเรียน การเรียน WS/AT การรับเงิน รายงาน และสต็อก พร้อมหน้าต่าง KSIS ภายในแอป

## อุปกรณ์ที่ใช้งานจริง

- ใช้งานบน PC ประมาณ 99% และ tablet ประมาณ 1% ตามที่เจ้าของระบบระบุวันที่ 24 พฤศจิกายน 2026
- ออกแบบและทดสอบขั้นตอนหลักสำหรับ PC โดยรักษาการใช้งานบน tablet ไม่ต้องออกแบบหน้าจอสำหรับ smartphone
- อย่าเปลี่ยนขั้นตอนงานเดิมหรือซ่อนข้อมูลสำคัญเพื่อรองรับจอโทรศัพท์

## เริ่มใช้งาน

ใช้ Node.js ตาม `engines` ใน `package.json` และ PostgreSQL ที่ตั้งค่าไว้ใน `.env`
ติดตั้ง dependency ด้วย `npm ci` จากโฟลเดอร์โปรเจกต์

- เปิดแอป Windows: `start-kumondb.bat` หรือ shortcut เดิม
- เปิดเฉพาะเว็บเซิร์ฟเวอร์: `npm start` แล้วเข้า `http://localhost:3000`
- พัฒนา: `npm run dev`

รายละเอียดหน้าต่างแอปและ session KSIS อยู่ใน [desktop/README.md](desktop/README.md)
การอัปเดตใช้ปุ่มอัปเดตเดิม ไม่ปรับโครงสร้างฐานข้อมูลอัตโนมัติ ดู [database/UPGRADES.md](database/UPGRADES.md)
และ [ขั้นตอนกู้การอัปเดตรุ่นเก่า](launcher/UPDATE-RECOVERY.md)

## โครงสร้างงาน

| ตำแหน่ง | หน้าที่ |
| --- | --- |
| `server.js`, `config/` | เริ่มระบบ ตั้งค่าฐานข้อมูลและบริการ |
| `routes/`, `middleware/` | API, session และสิทธิ์การใช้งาน |
| `services/` | กติกาธุรกิจ การอ่าน/บันทึกข้อมูล ธุรกรรม และ KSIS |
| `public/*.html`, `public/css/` | หน้าจอและรูปแบบการแสดงผล |
| `public/js/` | ตัวควบคุมหน้าเว็บและ helper กลาง |
| `public/js/worksheet/` | แยกส่วนค้นหา กรอก ประวัติ Preview และสอบ AT |
| `desktop/` | หน้าต่าง Electron, KSIS view และดาวน์โหลด |
| `migration/` | Preview และนำเข้าข้อมูลจากระบบเดิม |
| `database/` | SQL สำหรับติดตั้งและปรับฐานข้อมูลด้วยขั้นตอนที่ระบุไว้ |
| `launcher/`, `scripts/` | เปิด/อัปเดต/สำรองข้อมูล และเครื่องมือดูแลระบบ |
| `test/` | ทดสอบด้วยข้อมูลจำลองและฐานข้อมูลชั่วคราว |

## ใช้ฟังก์ชันกลาง

- `services/dateHelpers.js`: วันที่ของฟอร์ม/WS และวันที่ของสต็อก แยกค่าว่าง `""` กับ `null` ตามสัญญาเดิม ใช้วันที่ท้องถิ่น ไม่แปลงข้ามวันด้วย UTC
- `services/stockTypeResolver.js`: ค้นหารหัสประเภทสต็อก โดยแต่ละบริการมี config และ cache ของตัวเอง
- `migration/migrationValueHelpers.js`: ทำความสะอาดข้อความ แปลงค่า วันที่ และสรุปข้อผิดพลาดที่กติกาตรงกัน ส่วนกติกาเฉพาะการนำเข้าแต่ละชนิดยังอยู่ในโมดูลนั้น
- `public/js/httpUtil.js`, `htmlUtil.js`, `statusUtil.js`: request, escaping และแสดงสถานะ โหลดก่อน script ของหน้าเว็บ
- `public/js/inputSelection.js`: เลือกข้อความในช่องกรอก โดยไม่ผูกกับ state ของ Students หรือ Payment
- `public/js/worksheet/worksheetPreview.js`: อ่านเลข WS ชุดเดียวกันสำหรับ Preview และการบันทึก

ก่อนรวม helper ต้องเทียบเรื่องค่าว่าง รูปแบบ error วันที่ และผลข้างเคียงด้วย
อย่ารวมเพียงเพราะชื่อฟังก์ชันเหมือนกัน และอย่าย้ายขอบเขต transaction ไปไว้ใน helper ทั่วไป
คง export เดิมของ Worksheet และ Student form เพื่อไม่ให้ผู้เรียกต้องเปลี่ยนตาม

## ขอบเขตการดูแลโค้ด

- ก่อนลบโค้ด ต้องตรวจการเรียกจาก HTML, event handler, route, launcher และเครื่องมือที่รันด้วยมือด้วย
- ไฟล์รองรับการอัปเดตจากรุ่นเก่าและ entry point เดิมอาจยังจำเป็น แม้ไม่มี import ปกติ
- โมดูลหลัก Students และ Worksheet มีการอ้างอิงกลับกัน ให้ใช้ URL เดียวกันและไม่เติม version query ที่ทำให้เกิด state ซ้ำ
- เก็บ `.env`, `backups/`, `logs/`, ไฟล์ต้นทางการนำเข้า และข้อมูลผู้ใช้ไว้นอก Git ไม่ลบทิ้งระหว่างจัดโค้ด
- การจัดโค้ดไม่ใช่การอัปเดตฐานข้อมูล และไม่ควรเปลี่ยนกติกาค่าเรียน สถานะ หรือสต็อกไปพร้อมกัน
