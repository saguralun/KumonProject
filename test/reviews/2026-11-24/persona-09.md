**รายงานบทบาท 09 — ผู้ดูแลสามเครื่องที่ไม่ถนัดเทคนิค**

ตรวจจาก working tree ปัจจุบัน รวมไฟล์ใหม่และ cleanup ที่ยังไม่ commit ด้วยการอ่านโค้ดและตัวทดสอบเท่านั้น **ไม่ได้คลิกจริง เปิดเบราว์เซอร์ รันทดสอบ อ่าน `.env` หรือเชื่อมระบบจริง และไม่ได้แก้ไฟล์ใด** ข้อพบด้านล่างเป็นปัญหาที่ยังอยู่ในโค้ดปัจจุบัน ไม่ได้ยืนยันว่า cleanup เป็นสาเหตุ

**1) บุคลิกและงานเป้าหมาย**

ผู้ดูแลต้องเปิดโปรแกรมให้สามเครื่องใช้งาน แยกให้ออกว่าเครื่องไหนเป็นเครื่องแม่ อัปเดตโดยไม่รบกวนงานที่ยังไม่บันทึก และนำข้อมูลกลับได้เมื่อเลือกไฟล์ผิด ผู้ใช้กลุ่มนี้ทำตามปุ่มและข้อความได้ แต่ไม่ควรต้องรู้จัก Git, npm หรือค้นไฟล์ log เอง

- **ผลกระทบเชิง UX:** ผู้ใช้สามเครื่องอาจประเมินขอบเขตการทับข้อมูลผิด การพิมพ์ชื่อฐานยังไม่ช่วยแยกเครื่องที่ใช้ชื่อฐานเหมือนกัน **ยังไม่ได้ยืนยันว่าการติดตั้งจริงใช้ฐานร่วมกันหรือชื่อซ้ำ**
- **ปรับเล็กและชัด:** เปลี่ยนข้อความเป็น “ฐานข้อมูลบนเซิร์ฟเวอร์ … ซึ่งเครื่องอื่นที่เชื่อมอยู่ใช้ร่วมกัน” และแสดงชื่อเครื่องแม่กับชื่อฐานติดกับปุ่มและในกล่องยืนยัน ใช้ป้าย “ใช้งานจริง/ทดลอง” หากมีการตั้งค่าไว้

หลักฐาน test ที่อ้างเป็นการอ่าน assertion ไม่ใช่ผลรันรอบนี้ และไม่ได้ตรวจการตั้งค่าจริง จึงยังไม่ทราบว่าสามเครื่องใช้เซิร์ฟเวอร์เดียวกันหรือเป็นสามชุดแยก

กรณีที่ควรให้ parent จำลองแบบควบคุมทรัพยากร:

- เปิด shortcut เมื่อ dependency หาย/เปิด Desktop ไม่สำเร็จ: ผู้ใช้เห็นอะไรนอกหน้าต่างคำสั่งที่ซ่อนอยู่
- อัปเดตผ่าน LAN จากเครื่อง B: ทุกข้อความระบุเครื่องแม่และผลต่อเครื่องอื่นได้ชัดหรือไม่
- helper ล้มหลัง `READY` โดยเซิร์ฟเวอร์เดิมยังอยู่: วัดเวลาที่ UI แจ้งล้มเหลวและกลับมากดใหม่ได้
- ตัดอินเทอร์เน็ตระหว่าง pull กับติดตั้ง: ผู้ใช้ทำต่อผ่านปุ่มได้โดยไม่ต้องเปิดคำสั่งหรือไม่
- Restore ผิดไฟล์และ Restore ล้มเหลวบนฐานชั่วคราว: ให้ผู้ใช้หาดาวน์โหลดไฟล์ก่อน Restore และกู้กลับตามข้อความบนจอ
- เปิดสองเครื่องลูกค้างไว้ระหว่างเครื่องแม่อัปเดต/Restore: ตรวจข้อความค้างและการกลับมาใช้งาน โดยยังไม่สรุปว่ามีปัญหาการเขียนพร้อมกันจากการอ่านครั้งนี้
